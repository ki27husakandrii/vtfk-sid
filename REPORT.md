## 2. Відповіді на контрольні питання
1. **Чому всередині PID 1, а на хості інший?** Контейнер працює у власному PID namespace, де його процес стає коренем дерева (PID 1). На хості він отримує звичайний системний номер.
2. **Чому ядро те саме і як перевірити?** Docker ділить спільне ядро хоста. Перевірка: `uname -r` дає однаковий результат на хості й у контейнері.
3. **Що буде з портом без -p?** Помилка `Connection refused`. Без `-p` Docker не робить NAT-переадресацію (DNAT) на хості.
4. **Різниця між -p 8080:80 та 80:80?** Порт 80 — привілейований (<1024), вимагає прав root і може конфліктувати зі службами хоста. 8080 — вільний користувацький порт.
5. **echo $$ у контейнері і на хості — це один процес чи два?** Один процес (`task_struct`). Ядро просто проектує його номер у різні namespaces. Якщо на хості зробити `kill <хост_PID>`, процес у контейнері впаде.
6. **Чому bash-скрипт кращий за ручне введення?** Повна повторюваність результату, відсутність помилок людського фактору, легка інтеграція в CI/CD.
7. **Що покаже ps aux на хості для процесу контейнера?** Звичайний рядок процесу хоста з його реальною командою і системним PID.
8. **Навіщо видаляти контейнер перед docker run?** Демон Docker забороняє створювати дублікати імен. Без `docker rm -f` другий запуск скрипту впаде з помилкою 125.
